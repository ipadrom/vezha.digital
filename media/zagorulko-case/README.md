# Кейс ИП Загорулько

`content.json` содержит тексты, ссылки на медиа и обложку на двух языках. `apply-local.mjs` сохраняет и публикует документ через локальный API админки; `apply-cover-local.mjs` изменяет только обложку. Снимок для доставки находится в `backend/alembic/data/zagorulko_refresh_20260918.json` и применяется миграцией `k7z8a9b0c1d2`. Применённый снимок не редактируется: последующие правки выполняются в админке или новой миграцией.

В кейсе девять блоков: шапка, обложка, вводная часть, четыре сценария, результаты и один сгруппированный стек. Показатели времени предоставлены заказчиком. Пример Google Таблиц показывает заказы «Элит»: два заказа учтены, один оставлен на проверку; суммарно восемь единиц с половинными долями.

Медиа находятся в `frontend/public/cases/gbu-process-automation/2026-09/`. `orders-recorded.mp4` и `crews-recorded.mp4` подготовлены из записей пользователя: панель браузера и боковые поля обрезаны, звук удалён, итоговый кадр задержан на две секунды. Общий элемент этапов воспроизводит видео без панели управления, по кругу; при системном уменьшении движения остаётся постер.

`build-cover.mjs` собирает SVG из предоставленных мокапов и настоящего скриншота. Логотип и надписи — отдельные SVG-элементы; экран ноутбука заполняется без растяжения. Обложка общая для карточки проекта и первого медиа-блока.

## Ролики этапов

Девять пунктов, которые раньше показывались скриншотами, заменены короткими записями: правка заказа, перенос и закрепление бригад, история составов, загрузка заказов из чата, фото-контроль, сохранённая очередь и три сценария Google Таблиц. Исходники — `record/` (тот же конвейер, что и `media/mymit-case/record`: Playwright с покадровым захватом через CDP в масштабе 2×, курсор и нажатия дорисовываются, `ffmpeg` собирает H.264 без звука, постер — кадр из ролика). Зависимости ставятся `npm install` в `record/`; `DRY=1` сохраняет скриншоты шагов вместо видео, `OUT_DIR` переопределяет папку вывода.

`record/app.mjs` пишет шесть роликов рабочего центра с оффлайн-стенда `gbu-center/output/mobile-case-2026-09-07/serve_demo.py` (127.0.0.1:8097, синтетические люди, временный каталог, без `.env`). Перед записью стенд перезапускается, чтобы история была пустой. В шапке «ГБУ» заменено на «ИП Загорулько», пометка — «Демо»; сервис-воркер PWA блокируется, иначе запросы уходят мимо перехвата. Перехватываются только `/ocr` (ответ из `fixture.json`, полоски исходника нарисованы из той же вымышленной таблицы), `/state/`, чтение исходного чата и запуск/статус операций MAX: сообщения статусов повторяют тексты `routes.py`. Правка полей, перетаскивание, закрепление, пересборка, разбор и сохранение дня, сокращение заказов выполняет код приложения; сообщения в MAX не отправляются. Ролик очереди перезагружает страницу посреди отправки — захват на время перезагрузки приостанавливается.

`record/sheets.mjs` пишет три ролика с постановочной копии таблицы `sheet-stand/index.html`: оформление Google Таблиц, меню «Заказы» с пунктами из `Main.gs`, баннер выполняющегося скрипта, кнопка «Прибавить все неприбавленные заказы» и тексты итоговых сообщений повторяют рабочий скрипт `gbu-misha/google-apps-script`. Это не настоящий Google Sheets и не подключённый Apps Script; в подписи к роликам это указано. Данные — тот же вымышленный срез «Элит», что и на прежних скриншотах.

`apply-videos-local.mjs` подставляет ролики в локальный кейс через API админки по заголовкам пунктов; тот же патч `backend/alembic/data/zagorulko_videos_20260925.json` применяет миграция `w9f0a1b2c3d4` к строкам блоков и опубликованному снимку, сохраняя отредактированные описания. Прежние PNG оставлены в папке: на них ссылаются ранее опубликованные снимки.

## Двойные ролики с настоящим чатом MAX

`source-live.mp4` и `final-live.mp4` записаны `record/live.mjs`: слева рабочий центр, справа настоящий web.max.ru, обрезанный до окна переписки. Стенд `record/serve_live.py` запускает приложение с инстансом GREEN-API владельца из `gbu-center/.env`, но с локальным хранилищем (S3 отключён, временный каталог), без очереди в облаке и только с тремя демонстрационными группами в настройках чатов (ссылки берутся из git-ignored `record/live-groups.json`); пароль стенда генерируется на каждый запуск и лежит в git-ignored `live-auth.json`. Вход в web.max.ru делает владелец один раз в окне `record/max-login.mjs`; сессия хранится в git-ignored `record/max-profile/`, скрипты не вводят учётные данные. Заказы в группу «Элит демо» отправлены через инстанс владельца (пять вымышленных заказов на следующий день, один без бригады). В `final` сообщения действительно отправляются в группу «Фото сбора финал демо» с паузами приложения между ними, поэтому ролик длится около 40 секунд. Фото-контроль по решению владельца не снимался: в демонстрационных группах нет участников. Одиночные версии `source.mp4` и `queue.mp4` (последняя показывает восстановление статуса после перезагрузки страницы) оставлены в папке, но в кейсе не используются.
