## Состав

`case.json` — русский и английский документы штатного конструктора: шапка, обложка, вводная, семь направлений доработок с 24 конкретными пунктами, результаты и сгруппированный стек. Используются существующие `overview`, `chapter`, `air` и `contours`.

`frontend/public/cases/mymit/2026-09/` содержит 12 коротких роликов (`*.mp4` с постерами `*.jpg`) и 9 фрагментов настоящего интерфейса из изолированной дев-версии на `http://localhost:3080` (ветка `dev`). Ролики показывают действие целиком: нажатие на сердце и появление кабинки во вкладке избранного, ввод запроса в поиск, полный тур обучения, вход по телефону, выбор даты и интервала, ранний старт, перенос, продление, минуты с баланса, скидку за повторное посещение, фильтры аналитики и списка бронирований. Прежние PNG этих пунктов оставлены в папке: на них ссылаются ранее опубликованные снимки кейса. T Relay, OTA и копейки описаны текстом. Среди показанных состояний: избранное, поиск, перенос, сохранённая оплата, расчёт продления, минуты с баланса, график выручки, фильтр бронирований и выбор MQTT-провайдера. Дополнительно показаны резервные каналы входа, обучение, часы работы, проверка интервала, ранний старт, условия дополнительного времени, персональные лимиты промокодов, аудитория Push-рассылок, голосовые события и состояние устройства. Фрагменты сняты непосредственно браузером без дорисовки интерфейса и рамок смартфонов.

Данные демонстрационные; суммы, количество броней и загрузка на экранах не являются показателями клиента. `seed-sandbox.py` создаёт синтетические записи только в изолированном MyMIT sandbox и проверяет его окружение перед записью. Платежи не отправляются провайдеру, физическое оборудование не используется. В PowerShell перед передачей скрипта в контейнер необходимо установить `$OutputEncoding=[System.Text.UTF8Encoding]::new()`.

Изображение кабинки и логотип взяты из публичных брендовых ресурсов MyMIT. Обложка — SVG-композиция этих материалов и двух общих экранов приложения (`booking.png`, `bookings.png`), без рекламных подписей. Дизайн кабинки не приписывается агентству.

## Видео

Ролики пишутся скриптами в `record/` с того же стенда: `node record/user.mjs [сценарий…]` — пользовательские сценарии, `node record/admin.mjs [analytics|bookings|returnvisits]` — административные. Нужны Playwright (`PLAYWRIGHT_MODULE` может указывать на установленный модуль) и `ffmpeg` в `PATH`; `DRY=1` сохраняет скриншоты шагов вместо видео, `OUT_DIR` переопределяет папку вывода (по умолчанию — папка фрагментов). Перед записью выполняется `seed-sandbox.py`: он задаёт демо-кабинкам координаты для карты, ставит служебную кабинку стенда в конец списка и выдаёт демо-пользователю бонус повторного визита. Сценарии `earlystart` и `reschedule` меняют состояние стенда (активируют и переносят бронь) и сами пересеивают данные; `favorites` сбрасывает избранное демо-пользователя.

Захват идёт покадрово через CDP `Page.captureScreenshot` в масштабе 2× (screencast отдаёт только CSS-пиксели), кадры собираются `ffmpeg` в H.264 без звука; курсор и нажатия дорисовываются поверх страницы. Область обрезки берётся по элементам с отступом не меньше 24 px, чтобы скругление рамки в кейсе (18 px) резало только фон приложения; для экранов, у которых после действия меняется высота (вход, аналитика, модальные окна), область измеряется в конце сценария. Логин стенда ограничен rate limit: токен синтетического аккаунта кешируется в файле рядом со скриптами, а при HTTP 429 помогает перезапуск контейнера backend.

## Обновление

1. `capture.mjs` снимает девять фрагментов запущенного изолированного стенда после подготовки синтетических записей. Для переноса выбирается дата через три дня в открытом месяце календаря; при переходе месяца её нужно предварительно открыть. Требуется Playwright; `PLAYWRIGHT_MODULE` может указывать на уже установленный модуль. Авторизация проходит через стандартный API стенда; состояние авторизации остаётся в памяти браузера. Повторные запуски ограничены обычным rate limit входа — при HTTP 429 дождаться его окончания.
2. `node media/mymit-case/build.mjs` собирает обложку и документ из авторских текстов. Перед повторной сборкой учитывать правки, сделанные в локальном редакторе: скрипт заменяет содержание документа, сохраняя идентификаторы блоков по типу, раскладке и заголовку.
3. `node media/mymit-case/apply-local.mjs` сохраняет и публикует **только локальную** версию через штатный API на localhost:8000. Публикация нужна для просмотра публичного рендерера на локальном стенде. Production, миграции, Git commit/push скрипт не затрагивает.

Для просмотра использован отдельный Nuxt dev server на 127.0.0.1:3100 с локальным API localhost:8000. Уже запущенный контейнерный frontend на 3000 в момент работы отображал только шапку даже для существующего ССАГ; его конфигурация не менялась.

Миграция `s5b6c7d8e9f0` переносит ролики и новые пункты в уже созданный кейс, сопоставляя пункты по заголовку и сохраняя остальные редакторские правки (её первый выпуск обновил только опубликованный снимок, поэтому `v8e9f0a1b2c3` повторяет патч для черновика); снимок `backend/alembic/data/mymit_case_20260921.json` обновлён до того же содержания и по-прежнему равен `case.json` без блока заказчика.
